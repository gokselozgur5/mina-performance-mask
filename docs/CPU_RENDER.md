# Offline CPU render runbook

## Verified result

On 2026-10-24, the private full-length CPU run completed successfully:

- 16 seconds, 400 frames, 25 fps.
- H.264, 512 x 960, 1,766,634 bytes.
- Full FFmpeg decode succeeded; the local copy matched the Thor SHA-256.
- The owner reported a promising first result with some visual anomalies.
  Anomaly types and timestamps have not yet been characterized.

Exact inference elapsed time was not recorded in this verification. Do not
interpret output frame rate as rendering speed or claim real-time readiness.

The tested host uses L4T R38.4, CUDA 13.0, native PyTorch 2.12.1+cu130, and
TensorRT 10.13.3.9. GPU inference reset the board in both MAXN and 120 W
profiles. Do not retry GPU inference on this stack. CPU execution is the
working offline baseline; the GPU failure's root cause remains unproven.

## Prepare and run

Use the input-preparation commands in the [README](../README.md). Keep the
portrait, driving clip, weights, templates, logs, and outputs in private
storage outside Git. Use the pinned upstream revisions in `config/` and an
existing environment with the official LivePortrait weights installed.
This runbook assumes that environment is already provisioned.

Activate that Python environment, then run from this repository:

```bash
export LIVEPORTRAIT_DIR=/path/to/LivePortrait
export CUDA_VISIBLE_DEVICES=''
export OMP_NUM_THREADS=8
./scripts/render-liveportrait.sh \
  /private/input/mina-source.png \
  /private/input/driving.mp4 \
  /private/output \
  cpu
```

The CPU backend adds `--flag-force-cpu --no-flag-use-half-precision`.
Use a persistent terminal session such as tmux for a long render and keep its
log private. The recorded retry used eight OpenMP threads; this is not a
claim that eight is the optimal setting for every machine.

## Reuse or recover a motion template

A successful video run writes a private `.pkl` motion template beside the
driving video. A valid template can replace the MP4 argument on a later run;
LivePortrait then skips video cropping and motion-template extraction.
Only load templates generated by your trusted local workflow: pickle files
can execute code when loaded. Templates remain private motion data.

The first full-run attempt failed with `EOFError: Ran out of input` because
its template was zero bytes. The recovery was to supply the original MP4 to
a CPU-only retry, regenerating the 400-frame template. Do not repeatedly
retry a broken PKL or switch to GPU to address this file error.

The wrapper now rejects an empty driving input before launching inference.
A nonempty file is not proof that a template is valid; interrupted nonempty
templates may also require regeneration from the original video.

## Verify and retrieve only the Mina output

Check successful process completion and inspect the output metadata:

```bash
ffprobe -v error \
  -show_entries format=duration,size:stream=codec_name,width,height,nb_frames,r_frame_rate \
  -of json /private/output/mina-source--driving.mp4
ffmpeg -v error -i /private/output/mina-source--driving.mp4 -f null -
```

Substitute the actual filename emitted by LivePortrait. Compare SHA-256 on
Thor and the local copy after transfer. Copy only that explicitly named
Mina-only MP4; do not use an output-directory wildcard. Leave `_concat.mp4`
on Thor because it can show the private performer footage.

A successful decode and matching checksum establish file integrity, not
visual quality. Review the full Mina-only clip locally for identity drift,
eyes, teeth, lips, jaw, hair, background, and face-boundary artifacts.

## Public repository boundary

Only source code and English technical documentation may be published here.
Never upload the performer's face, Photo Booth recording, raw driving video,
concat output, private inputs, model weights, or render outputs to GitHub or
another external service. Keep credentials out of commands, scripts, files,
and logs; use an authenticated SSH session or transient credential handling.

Before every commit and push, inspect the staged paths and tracked Git tree
for media, model, template, and private-artifact files. Git ignore rules alone
do not protect files already tracked or explicitly force-added.
